# 图片需求清单与规范

## 常见必需图（按章节）

| 章节 | 图片 | 优先级 |
|------|------|--------|
| 项目概述 | 项目 Logo、产品主图 | 建议 |
| 系统架构 | 架构图（分层 / 模块） | 必需 |
| 功能模块 | 功能模块图、核心功能界面截图（每个功能 1 张） | 必需 |
| 技术方案 | 数据流图 / 时序图、数据库 ER 图 | 必需 |
| 创新点 | 对比图、差异化示意图 | 建议 |
| 部署 / 测试 | 部署架构图、测试结果截图 | 建议 |
| 团队 | 团队合影、指导老师 | 可选 |

## 命名规范

统一放进 `images/` 文件夹，按章节序号 + 语义命名：

- `fig1-1-architecture.png`（第 1 章第 1 张图）
- 或 `01-architecture.png`、`02-ui-home.png`

禁止空格和特殊字符，用 `-` 连接，全部小写。

## 格式与尺寸

- 优先 PNG / JPEG；截图用 PNG
- 宽度建议 ≥ 1280px；架构图、流程图要清晰可读
- md 中统一写作 `![图注](images/xxx.png)`

## 缺失处理

- 必需图缺失：明确列出，询问用户"补图 / 用文字替代 / 用简化示意图"
- 建议图缺失：可跳过，向用户说明
- 用户额外提供的图：登记进清单，询问是否加入对应章节，不擅自丢弃

## 图片映射表（image-map.md）

独立于 .md 的图片说明文件，放在 `images/` 文件夹里，给不能看图的 AI 提供图片内容信息。
内容只有两列：**图片相对路径（相对 images/）+ 图片描述**。

```markdown
| 相对路径 | 图片描述 |
| --- | --- |
| fig1-1-architecture.png | 系统总体架构图：感知层/服务层/应用层三层，含蓝牙信标、地图服务、小程序端 |
| fig2-1-home.png | 儿童端首页：虚拟宠物形象居中，下方心情日记、情绪树洞入口 |
```

### 生成方式

- 用户提交图片时用口头 / 文字说明每张图的内容，AI 自动整理成 `images/image-map.md`
- 只给文件名也行，AI 推断出描述后请用户确认
- 新增图片时追加条目，不删用户提供的图
- 描述不确定时向用户确认，不猜测

### 使用方式

- 仅当 AI 无法直接查看图片时读取，作为图片内容的替代信息
- 与 .md 引用、图注、校验无关；md 的图片写法按正常 Markdown 规则即可

## 校验

用 `scripts/check_images.py` 检查 md 图片引用与 `images/` 文件夹是否一致，缺失时返回非 0。
