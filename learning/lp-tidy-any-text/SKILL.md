# LP_TidyAnyText — 通用学科资料整理工具

---

## 一、触发后第一步：探查 → 生成 rule.md → 交互

Skill 被触发后，**不要直接开始整理**。按以下顺序：

### 1. 读用户输入

从用户消息中提取：
- 学科名称
- 源文件所在目录（用户可能说"文件在 1/ 里面""资料在 docs/ 下"等）
- 特殊要求（哪些不考、哪些重点、输出偏好等）
- 用户身份

### 2. 探查实际目录

**以用户提到的路径为准**，列出源文件。如果用户没提，检查 `scource/`、当前目录、或常见资料目录。

探查内容：
- 有哪些文件（遍历目录，列出文件名、类型、大小）
- 文件是否能正常读取（PDF 是否为图片型、DOC 是否能打开等）
- 文件名中是否能推断章节信息

### 3. 生成 `rule.md`

读取 `references/rule.md` 作为模板，结合探查结果，在工作区根目录生成 `rule.md`，包含：

**AI 自动填写：**
- 源文件路径和清单（使用用户指定的目录路径）
- 文件名中推断出的章节线索

**用户需填写：**
- 学科名称、用户身份、时效性要求
- 要整理的内容类型
- 各章节内部顺序
- 输出文件结构
- 特殊要求

**AI 判断需要用户确认的事项**（根据探查结果动态生成，例如）：
- "发现 X 个 PDF 为图片型，需要 OCR 处理，预计耗时较长，是否继续？"
- "检测到文件 `XXX.doc` 为旧版格式，可能无法完整提取，建议转为 DOCX"
- "源文件名没有明显的章节信息，请提供课程目录"
- "发现 A 文件和 B 文件内容可能重复，优先采用哪个？"
- "检测到用户提到'XX 不考'，但未说明是整章不考还是某节不考，请确认"
- 其他 AI 在探查中发现的、无法自行决断的问题

**默认规则**（AI 执行参照，与用户要求冲突时以用户为准）

### 4. 等待用户确认

`rule.md` 末尾提示用户回复"继续"或"已填写完"。

用户确认后，AI 读取 `rule.md` 最终内容作为工作规则。**用户未填的用默认规则补全，AI 提的问题用户没回的由 AI 自行判断。**

## 二、工作区目录结构

**以用户指定的路径为准。** 用户可能说"文件在 1/ 里面""输出到 out/"，则按用户说的来。

若用户未指定，默认结构如下（所有目录均在当前工作区内创建）：

| 目录 | 用途 |
|------|------|
| `scource/` | 原始杂乱文件 |
| `parse/` | 转化后的 .md/.txt |
| `integrate/` | 按章节整合的中间文件 |
| `output/` | 最终输出文件 |
| `analyse/` | AI 操作日志和思考分析 |

---

## 三、六步工作流程

每步完成后记录操作日志到 `analyse/`。

### 第1步：环境准备

- 检查 Python 3.8+ 及所需库（`pdfplumber`、`pypdf`、`pypdfium2`、`python-docx`、`pytesseract`）
- 缺失则 `pip install`
- 如需 OCR：Tesseract 便携版下载到工作区 `tools/tesseract/`，中文语言包到 `tools/tessdata/`
- **所有下载一律放工作区内**，不碰 C 盘
- 日志 → `analyse/01-环境准备日志.md`

### 第2步：源文件转化（→ parse）

| 格式 | 方法 |
|------|------|
| PDF（文字型） | `pdfplumber` |
| PDF（图片型） | `pypdfium2` 渲染 + `pytesseract` OCR（scale=2~3） |
| DOCX | `python-docx` 段落+表格 |
| DOC（旧版） | `python-docx` → `antiword` → 失败则提示用户转为 DOCX |
| XMIND | 解压 ZIP → `content.xml` 或 `content.json` |
| 图片 | `pytesseract` OCR |

- 输出 UTF-8 `.md` 到 `parse/`
- CID 编码乱码 `(cid:XXXX)` → 正则 `chr(int(num))` 解码
- 空内容文件 → 标记"需人工处理"
- 日志 → `analyse/02-文件转化日志.md`

### 第3步：了解课程背景

- 读 `rule.md` 中的学科名称和用户身份
- 上网搜索该课程的教学大纲、主流教材、章节结构、常见考点
- 结果写入 `analyse/03-课程调研.md`

### 第4步：按章节整理分类（→ integrate）

1. 以 `rule.md` 中的章节结构组织内容
2. 读 `parse/` 全部文件，归类到对应章节
3. **去重**
4. 每章生成一个 `.md` 到 `integrate/`

**各章节内部顺序以 `rule.md` 中用户指定的为准**（非固定）。

### 第5步：错误检查

- **答案校验**：不同来源交叉对比 → 不一致则上网查证
- 修正内容按默认规则用小号标注：`<small>（修正：...）</small>`
- 时效性问题同样小号标注
- 日志 → `analyse/05-错误检查日志.md`

### 第6步：最终输出（→ output）

按 `rule.md` 中指定的输出方式和样式生成最终文件。

日志 → `analyse/06-最终输出日志.md`

---

## 四、核心原则

1. **先探查再生成 rule.md，用户确认后再干活**
2. **以用户说的路径和规则为准**，没说才用默认
3. **用户不填的，用 rule.md 默认规则补全**
4. **探查中发现的无法决断的问题，写入 rule.md 让用户决策**
5. **所有下载/临时文件放工作区内**，不碰 C 盘
6. **准确性优先**：不确定的内容标注"待确认"，不编造
7. **每步记录日志到 analyse/**
