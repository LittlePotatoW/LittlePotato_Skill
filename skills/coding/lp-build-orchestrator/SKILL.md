# 按需并行构建

用子代理协助完成有明确边界的软件构建任务，主代理负责需求判断、任务分派、整合和最终结果。当前配置的 `lp01`、`lp02`、`lp03` 是通用代理示例，均可承担代码库调研、简单代码实现、代码审查、测试或验证，并使用 `gpt-6-luna`；它们不是数量上限，也没有固定专岗。

## 何时调用

- 小型、单文件或顺序依赖明显的任务：直接处理，不启动代理。
- 涉及多个文件、需要先摸清陌生项目，或存在可独立实现的组件：按需决定代理数量。
- 用户指定代理数量时，按指定数量启动并分派独立工作；如果平台限制无法满足，说明实际限制和可启动数量。
- 并行工作应有不同文件或清楚的边界。避免让多个代理同时编辑同一文件。

## 协作方式

1. 将工作拆成目标明确、彼此独立的单元，例如调研一个模块、实现一个小组件、审查一组改动或验证一个行为。
2. 由主代理根据独立工作单元数量决定启动多少个代理，不限于当前示例中的三个。用户指定数量时优先遵循；每个代理都分配清晰的独立任务，也可按用户要求对不同文件或不同审查角度并行检查。
3. 可复用 `lp01`、`lp02`、`lp03`，也可按需启动其他代理实例或增加代理配置。新建自定义代理时沿用通用职责，并在平台支持时将模型设为 `gpt-6-luna`；不假定代理编号代表固定角色。
4. 需要时可将调研、实现和审查/测试分别交给不同代理；是否采用这些角色由任务决定。并行编辑时避免代理同时改同一文件，除非用户明确要求对同一目标进行多路独立审查。
5. 等待已分派工作完成，检查并整合结果、解决冲突。主代理对需求覆盖、验证决策和最终答复负责。

如果项目代理不可用、未加载或当前环境不支持按名称调用，继续由主代理完成任务，不要声称已经委派。遵守用户给出的范围与仓库约定；不要因并行工作扩大修改范围。是否运行测试按用户要求和仓库约定决定，并准确报告验证结果。
