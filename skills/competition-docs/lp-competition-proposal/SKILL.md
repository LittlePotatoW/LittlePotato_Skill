# LP_CompetitionProposal — 比赛项目计划书生成器

## 定位

把"代码 + 材料 + 调研"变成一份完整、可继续转 Word 的项目计划书 `.md`。
只做文档编排与调研补全，**不编造代码事实**。

采用**逐块交付**工作流：每块开工前列图片需求、收集图片、更新 image-map、
写内容、汇报确认，避免一次性闷头做完。最终产出**正式版**计划书：
按官方模板章节结构、正文无草稿味、重点章节详细展开、用户图片全量插入。

## 开场必问（阶段 0）

按 `references/opening-questions.md` 的必问项一次问齐（材料、图片、目标步骤、
比赛类型、代码版本关系、旧草稿残留、脱敏、交付范围、旧数据沿用、模板格式、
重点章节、图片提供方式、汇报粒度），整理成材料清单让用户确认，确认后才进入阶段 1。

## 工作流程

### 阶段 0.5：赛事调研

- 检索赛事官网 / 通知 / 补充通知 / 备赛经验贴，产出 `01-赛事介绍.md`：
  赛事全称、参赛组别、参赛要求、提交材料、时间线、评审维度、备赛经验、信息来源链接
- 专项赛（如"挑战杯·东北振兴产业升级专项赛"）特别记录：主题落位（如"五大安全"）、
  脱敏要求、落地意愿加分项

### 阶段 1：模板与示例研读 + 需求确认与方案

**必须先读官方模板与标准示例，再定章节结构，不自创结构。**

- 读官方模板（`.doc` 老格式用 Word/WPS COM 或二进制文本提取，读不出也要想办法），
  记录：比赛要求的章节标题、每章内容要求、字数限制、正文格式与图表格式说明
- 读用户提供的标准示例计划书（如往届获奖作品或同类项目），作为内容深度与写法的蓝本
- 产出 `00-需求文档.md`（项目定位、素材清单、已确认决策）
- 产出 `02-计划步骤.md`（工作区结构 + 块目录：每块内容 / 来源 / 图片需求 / 状态；
  重点章节允许自定义拆分；**执行摘要最后写**）
- 块目录先给用户确认，确认后才执行

### 阶段 2：调研块先行（每块留痕）

- 按块目录依次产出调研块（论文引用 / 应用场景 / 竞品市场等）
- 每块双文件：原始材料 → `调研过程/<块名>/原始笔记.md`（带链接、带过程）；
  正式结论 → 工作区根文件（如 `03-调研-论文引用.md`）
- 事实标来源；多口径数据选"主口径 + 辅助口径"；末尾列"数据缺口与待确认项"

### 阶段 3：分块写作（逐块工作流）

- 按块目录逐块写作，每块走 `references/block-workflow.md` 固定六步
- **执行摘要最后写**（评委最先看，是全篇"销售话术"）
- 重点章节（研究历程 / 产品 / 技术 / 市场等）要**详细展开**：
  - 用三级标题体系（如 1、1.1、1.1.1），主次分明
  - 以标准示例为蓝本对齐内容深度，不写薄
  - 章节之间要有因果衔接（如"研究历程 → 切中行业需求 → 架构设计"），不跳逻辑
  - 算法、架构等核心内容必须展开讲清楚，不能一笔带过

### 阶段 4：正式版生成与校验

- 按官方模板章节结构汇总正式版（内容可来自草稿，但必须过"正式版产出规范"）
- 用 `scripts/check_images.py` 校验图片引用与 `images/` 一致
- **用户图片全量核对**：对照 `image-map.md`，确认用户提供的每一张图都已插入正文
  （未引用 = 要么补插、要么明确向用户说明原因）
- 核对字数限制（如模板要求正文 12000 字内）、数据来源标注

### 阶段 5：最终交付

- 汇报：完成章节、未覆盖的要求、仍缺失的材料 / 图片
- 排版转 Word 后续再做（届时套官方模板的字体 / 标题 / 图名表名格式）

## 正式版产出规范（核心，见 `references/formal-draft-rules.md`）

正式版计划书与工作区草稿是**两回事**：

- 正文不得出现草稿注释：待补充、待确认、图片来源、状态说明、"赛事要求（不超过多少人）"等
- 不得把"规划"写成"已落地"：原型阶段就写原型，应用场景写"规划的目标场景"，落地写"计划/依据"
- 不得夸大：原型不说"可落地产品"，预测数据标注"预期"，数据标来源
- 用户提供的图片全部合理插入对应章节，不遗漏
- 重点章节展开、三级标题、逻辑衔接（详见规范文件）

## 图片表达原则

- **优先文本 + 公式表达**，不主动用绘图脚本生成示意图
  （架构、流程、数据用文字、表格、公式、代码块表达）
- 用户提供的照片 / 截图按规范入 `images/` 并登记 `image-map.md`，正式版全量插入
- AI 无法看图时以 `image-map.md` 描述为准，不猜图、不编造

## 输出约定

- 最终产出：正式版 `计划书.md` + `images/` + `images/image-map.md`
- 中间产物：`00-需求文档.md`、`01-赛事介绍.md`、`02-计划步骤.md`、
  `调研过程/<块名>/原始笔记.md`、调研文件 `NN-调研-*.md`、草稿 `NN-草稿-*.md`
- 草稿与正式版分开放置（正式版可另建文件夹），互不污染
- 不覆盖用户已有文件；新文件放在工作区

## 核心原则

1. 代码事实不编造：功能、技术栈以代码为准，不确定就标注并询问
2. 调研结论标来源，数据不确定标"待确认"（草稿内）；正式版数据须标来源
3. 每块结束先汇报再继续，不一次性闷头做完
4. 材料缺失时明确列出并询问，不擅自跳过必需内容
5. 先读官方模板与标准示例，按模板定结构，不自创
6. 正式版去草稿味、不吹牛、规划与事实分明
7. 用户图片全量插入，不遗漏
8. 图片命名规范、路径统一指向 `images/`
9. 调研原始材料留痕（`调研过程/<块名>/`），正式产出与原始材料分离
10. 总进度文件（`02-计划步骤.md`）持续维护块状态
