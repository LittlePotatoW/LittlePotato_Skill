# LP_CompetitionProposal — 比赛项目计划书生成器

## 定位

把"代码 + 材料 + 调研"变成一份完整、可继续转 Word 的项目计划书 `.md`。
只做文档编排与调研补全，**不编造代码事实**。

采用**逐块交付**工作流：每块开工前列图片需求、收集图片、更新 image-map、
写内容、汇报确认，避免一次性闷头做完。

## 开场必问（阶段 0）

按 `references/opening-questions.md` 的必问项一次问齐（材料、图片、目标步骤、
比赛类型、代码版本关系、旧草稿残留、脱敏、交付范围、旧数据沿用、模板格式、
重点章节、图片提供方式、汇报粒度），整理成材料清单让用户确认，确认后才进入阶段 1。

## 工作流程

### 阶段 0.5：赛事调研

- 检索赛事官网 / 通知 / 补充通知 / 备赛经验贴，产出 `01-赛事介绍.md`：
  赛事全称、参赛组别、参赛要求、提交材料、时间线、评审维度、备赛经验、信息来源链接
- 专项赛（如"挑战杯·东北振兴产业升级专项赛"）特别记录：主题落位（如"五大安全"）、
  脱敏要求、落地意愿加分项

### 阶段 1：需求确认与方案

- 产出 `00-需求文档.md`（项目定位、素材清单、已确认决策）
- 产出 `02-计划步骤.md`（工作区结构 + 块目录：每块内容 / 来源 / 图片需求 / 状态；
  重点章节允许自定义拆分；**执行摘要最后写**）
- 块目录先给用户确认，确认后才执行

### 阶段 2：调研块先行（每块留痕）

- 按块目录依次产出调研块（论文引用 / 应用场景 / 竞品市场等）
- 每块双文件：原始材料 → `调研过程/<块名>/原始笔记.md`（带链接、带过程）；
  正式结论 → 工作区根文件（如 `03-调研-论文引用.md`）
- 事实标来源；多口径数据选"主口径 + 辅助口径"；末尾列"数据缺口与待确认项"

### 阶段 3：分块写作（逐块工作流）

- 按块目录逐块写作，每块走 `references/block-workflow.md` 固定六步
- **执行摘要最后写**（评委最先看，是全篇"销售话术"）
- 产品 / 技术等重点章节可拆成多个块，老版本 / 新版本等双线分别详写

### 阶段 4：汇总校验

- 用 `scripts/check_images.py` 校验全部 md 图片引用与 `images/` 一致
- 汇总为 `计划书.md`

### 阶段 5：最终交付

- 汇报：完成章节、未覆盖的要求、仍缺失的材料 / 图片
- 排版转 Word 后续再做（届时读取官方模板；`.doc` 老格式读不出时先按赛事要求定章节）

## 逐块图片流程（核心）

每个块开工前先给该块"图片需求清单"（必需 / 建议 + 每张图内容 + 状态），
用户提供后按规范命名入 `images/`，**立即**更新 `images/image-map.md`，
不等到最后统一补。详见 `references/block-workflow.md` 与 `references/image-checklist.md`。

## AI 生成示意图

架构图、流程图、数据图等示意图可由 AI 生成（推荐 `scripts/gen_figures.py` 集中管理，
matplotlib + 中文字体），生成后同样登记 `image-map.md`；照片类图片由用户提供，
并提供内容描述（AI 无法看图时以描述为准，不猜图）。

## 输出约定

- 最终产出：`计划书.md` + `images/` + `images/image-map.md`
- 中间产物：`00-需求文档.md`、`01-赛事介绍.md`、`02-计划步骤.md`、
  `调研过程/<块名>/原始笔记.md`、调研文件 `NN-调研-*.md`、草稿 `NN-草稿-*.md`
- 不覆盖用户已有文件；新文件放在工作区

## 核心原则

1. 代码事实不编造：功能、技术栈以代码为准，不确定就标注并询问
2. 调研结论标来源，数据不确定标"待确认"
3. 每块结束先汇报再继续，不一次性闷头做完
4. 材料缺失时明确列出并询问，不擅自跳过必需内容
5. 图片命名规范、路径统一指向 `images/`
6. AI 看不了图片时以 `image-map.md` 的描述为准，不猜图、不编造图的内容
7. 调研原始材料留痕（`调研过程/<块名>/`），正式产出与原始材料分离
8. 总进度文件（`02-计划步骤.md`）持续维护块状态
