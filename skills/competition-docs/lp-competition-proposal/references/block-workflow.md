# 逐块交付工作流（阶段 3 每块固定动作）

每个块开工前和完成后，固定执行以下六步，避免"一次性闷头做完"或"最后才补图"。

## 固定六步

1. **读块目录**：查看 `02-计划步骤.md` 中该块的内容、来源、图片需求，确认素材齐备
2. **列图片需求清单**：开工前先把该块的"图片需求清单"发给用户——
   - 每张图：文件名（建议命名）、内容说明、优先级（必需 / 建议）
   - 状态：已有（标注位置）/ 待用户提供 / 待 AI 生成
   - 必需图缺失时明确说明"补图 / 用文字替代 / 用简化示意图"
3. **收集图片**：用户提供（或确认 AI 生成）→ 按规范命名放入 `images/`
4. **立即更新 image-map.md**：新图马上登记（相对路径 + 图片描述），**不等到最后统一补**
5. **写该块内容**：md 中图片引用统一写 `![图注](images/xxx.png)`
6. **汇报确认**：汇报完成内容 + 待确认项 → 用户确认 → 进入下一块

## 规则

- 每块独立交付：用户确认后再继续，不跨块一次性写多个块
- 图片映射表自项目开始即建立（`images/image-map.md`），随块持续追加
- 用户提供图片时须附内容说明；只给文件名时，AI 推断后请用户确认
- AI 无法看图时，以 image-map 描述为准，不猜图、不编造图的内容

## 调研块的适配

调研块（论文引用 / 场景 / 竞品）通常图片少或无，走简化流程：

1. 开工前列该块图片需求（通常"必需图：无；建议图：可后生成"）
2. 原始材料写入 `调研过程/<块名>/原始笔记.md`
3. 正式结论写入 `NN-调研-*.md`
4. 汇报完成 → 确认 → 下一块
