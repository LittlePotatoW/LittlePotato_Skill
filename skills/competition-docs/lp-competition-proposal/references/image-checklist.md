# 图片需求清单与规范

## 常见必需图（按章节）

| 章节 | 图片 | 优先级 |
|------|------|--------|
| 项目概述 | 项目 Logo、产品主图 | 建议 |
| 系统架构 | 架构图（分层 / 模块） | 必需 |
| 功能模块 | 功能模块图、核心功能界面截图（每个功能 1 张） | 必需 |
| 技术方案 | 数据流图 / 时序图、数据库 ER 图 | 必需 |
| 创新点 | 对比图、差异化示意图 | 建议 |
| 部署 / 测试 | 部署架构图、测试结果截图 | 建议 |
| 实测验证 | 实验环境照片、设备照片、数据 / 界面截图 | 必需 |
| 团队 | 团队合影、讨论照片、指导老师 | 可选 |

## 逐块图片流程

不一次性列完全部章节的图；每个块开工前单独给该块清单：

1. 开工前列该块"图片需求清单"（必需 / 建议 + 每张内容 + 状态）
2. 用户提供（或确认 AI 生成）→ 按规范命名入 `images/`
3. **立即**更新 `images/image-map.md`（不等到最后）
4. 写该块内容，md 引用统一指向 `images/`

## 命名规范

统一放进 `images/` 文件夹，按块号 + 序号 + 语义命名：

- `fig-09-01-product-overview.png`（09 块第 1 张图）
- 禁止空格和特殊字符，用 `-` 连接，全部小写

## 格式与尺寸

- 优先 PNG / JPEG；截图用 PNG
- 宽度建议 ≥ 1280px；架构图、流程图要清晰可读
- md 中统一写作 `![图注](images/xxx.png)`

## AI 生成示意图

架构图、流程图、数据图、功能全景图等可由 AI 生成：

- 推荐用 `scripts/gen_figures.py` 集中管理（matplotlib + 中文字体，各图一个函数）
- 生成后同样按命名规范放入 `images/`，并登记 `image-map.md`
- 用户照片类图片仍由用户提供；AI 生成图需与代码 / 调研事实一致，不编造结构

## 用户照片描述要求

- 用户提交照片时须提供内容说明（口头 / 文字 / 文件名）
- AI 无法直接查看图片时，以 `image-map.md` 的描述为准，不猜图、不编造
- 只给文件名时，AI 推断描述后请用户确认

## 缺失处理

- 必需图缺失：明确列出，询问用户"补图 / 用文字替代 / 用简化示意图"
- 建议图缺失：可跳过，向用户说明
- 用户额外提供的图：登记进清单，询问是否加入对应章节，不擅自丢弃

## 图片映射表（image-map.md）

独立于 .md 的图片说明文件，放在 `images/` 文件夹里，给不能看图的 AI 提供图片内容信息。
内容只有两列：**图片相对路径（相对 images/）+ 图片描述**。

```markdown
| 相对路径 | 图片描述 |
| --- | --- |
| fig-09-01-product-overview.png | 产品功能全景图：四个产品卡片（桌面端/检测端/中控端/移动端）+ 部署形态 |
```

### 生成与维护

- 自项目开始即建立（初始为占位空表），随每个块持续追加
- 用户提交图片时用口头 / 文字说明每张图的内容，AI 自动整理登记
- 新增图片只追加条目，不删除用户提供的图
- 描述不确定时向用户确认，不猜测

## 校验

用 `scripts/check_images.py` 检查 md 图片引用与 `images/` 文件夹是否一致，缺失时返回非 0。
最终汇总阶段必须跑；每块加入时也可跑一次。
