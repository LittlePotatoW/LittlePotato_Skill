# 图片需求清单与规范

## 图片表达总原则

**优先文本 + 公式表达**：架构、流程、数据、功能树尽量用文字、表格、公式、代码块表达，
不主动用绘图脚本生成示意图。用户提供的照片 / 截图是正式版的主要图片来源。

## 逐块图片流程

1. 每个块开工前单独给该块"图片需求清单"（必需 / 建议 + 每张内容 + 状态）
2. 用户提供（或确认 AI 生成）→ 按规范命名入 `images/`
3. **立即**更新 `images/image-map.md`（不等到最后）
4. 写该块内容，md 引用统一指向 `images/`

## 命名规范

统一放进 `images/` 文件夹，按块号 + 序号 + 语义命名：

- `fig-09-01-product-overview.png`（09 块第 1 张图）
- 禁止空格和特殊字符，用 `-` 连接，全部小写

## 格式与尺寸

- 优先 PNG / JPEG；截图用 PNG
- 宽度建议 ≥ 1280px；架构图、流程图要清晰可读
- md 中统一写作 `![图注](images/xxx.png)`

## 用户照片 / 截图处理

- 用户提交图片时须提供内容说明（口头 / 文字 / 文件名）
- AI 无法直接查看图片时，以 `image-map.md` 的描述为准，不猜图、不编造
- 只给文件名时，AI 推断描述后请用户确认
- 用户额外提供的图：登记进清单，询问是否加入对应章节，不擅自丢弃

## 全量核对（正式版生成前必做）

对照 `image-map.md` 逐张核对用户提供的图片是否已插入正文：

- 已插入：确认图注 / 上下文正确
- 未插入：补插到合适章节；确实不用的，向用户说明原因
- 用 `scripts/check_images.py` 校验：md 引用全部存在、无缺失

## 缺失处理

- 必需图缺失：明确列出，询问用户"补图 / 用文字替代"
- 建议图缺失：可跳过，向用户说明

## 图片映射表（image-map.md）

独立于 .md 的图片说明文件，放在 `images/` 文件夹里，给不能看图的 AI 提供图片内容信息。
内容只有两列：**图片相对路径（相对 images/）+ 图片描述**。

```markdown
| 相对路径 | 图片描述 |
| --- | --- |
| fig-11-01-principle-frame-diff.png | 实验室原理验证：导师讲解帧间差分算法，锝-99 源实测 |
```

### 生成与维护

- 自项目开始即建立（初始为占位空表），随每个块持续追加
- 用户提交图片时用口头 / 文字说明每张图的内容，AI 自动整理登记
- 新增图片只追加条目，不删除用户提供的图
- 描述不确定时向用户确认，不猜测

## 校验

用 `scripts/check_images.py` 检查 md 图片引用与 `images/` 文件夹是否一致，缺失时返回非 0。
最终汇总阶段必须跑；每块加入时也可跑一次。
