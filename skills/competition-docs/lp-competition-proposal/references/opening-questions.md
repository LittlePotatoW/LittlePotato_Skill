# 开场必问与材料清单（阶段 0）

按顺序提问，回答后汇总成《材料清单》让用户确认。共 13 项必问，一次问齐，
避免反复打断用户。

## 必问项

### 1. 有什么材料

- 代码文件夹路径（本地目录）
- 项目计划书要求：评分标准 / 格式要求 / 章节要求（文件或粘贴文字均可）
- 已有草稿：是否已有 .md / Word / 零散文档
- 比赛背景材料：比赛通知、往届获奖作品、官网 / 白皮书 / 新闻（可给链接或文件）
- 其他：数据、访谈记录、测试报告、用户反馈

### 2. 能提供什么

- 图片：界面截图、架构图、流程图、Logo、实物照片等（说明大概有哪些）
- 图片描述：提交图片时能说明每张图是什么（口头 / 文字说明 / 或文件名本身）
- 数据：用户量、测试数据、调研数据
- 人力信息：团队成员与分工（实施计划章节需要）

### 3. 需要做到哪一步

- A：纯文字稿 + 图片需求清单
- B：收集图片后生成正式版 .md
- C：调研补全成最终 .md（竞品分析 / 背景 / 意义等）
- D：最终 .md + 转 Word（衔接 lp-md2docx）

### 4. 比赛类型

- 计算机设计大赛（技术文档，重架构 / 实现 / 测试）
- 互联网+ / 挑战杯（商业计划书，重市场 / 商业模式 / 财务）
- 挑战杯·专项赛（组别、专项主题、评审维度、脱敏、落地意愿——需赛事调研）
- 其他：请用户说明评分标准，以评分标准为准

### 5. 代码版本 / 分支关系

- 是否有旧版 / 分支版本？版本间是什么关系？（避免把同一套代码当两套写）
- 例：old-version-gammalens-python 分支与 GammaLensPython（V2.0）是同一个东西

### 6. 旧草稿甄别

- 已有草稿是否有其他项目的残留内容？（需剔除或标注，不混用）
- 例：旧商业计划书里混有另一个项目（疲劳驾驶监测）的章节

### 7. 脱敏要求

- 正文是否出现学校名 / 导师姓名？何时统一处理（暂不匿名 or 提交前处理）？

### 8. 交付范围

- 计划书 / PPT / 500 字简介 / 视频分别由谁做？本技能只做计划书还是全包？

### 9. 旧材料数据是否沿用

- 旧材料中的团队、财务等数据可信度如何？哪些明确不沿用（如 AI 生成的数字）？

### 10. 官方模板格式

- 模板是 .doc / .docx？能否读取？（WPS 老格式 .doc 可能读不出）
- 排版阶段再套模板，还是开头就定章节格式？

### 11. 重点章节

- 是否有重点章节需要拆分？拆分粒度（如"产品与技术"拆成多个块）？
- 多版本 / 多产品线是否需要分别详写？

### 12. 图片提供方式

- 截图 / 照片由用户提供；架构图、流程图、数据图是否可接受 AI 生成？
- 图片按块提供还是集中提供？

### 13. 汇报粒度

- 每块完成后确认，还是每阶段确认？
