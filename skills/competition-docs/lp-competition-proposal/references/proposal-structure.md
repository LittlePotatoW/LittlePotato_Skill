# 计划书章节骨架

## 第一原则：以官方模板为准

比赛官方模板（如挑战杯商业计划书模板）规定了章节结构、每章内容要求、字数限制与格式说明。
**必须首先读取官方模板与标准示例，按模板定章节结构，不自创。**

`.doc` 老格式模板读取方法：

- Word/WPS COM 组件（`New-Object -ComObject Word.Application` 等）
- 二进制文本提取（UTF-16 解码后正则提取中文片段）
- 读不出也要想办法（用户可能有 .docx 版本或标准示例）

## 官方模板示例（第十五届挑战杯商业计划书模板）

| 章节 | 内容要求 |
|---|---|
| 一、执行摘要 | 项目概述、优势、商业模式、财务融资，800 字内 |
| 二、项目概述 | 项目背景（行业态势/市场规模/痛点）、项目概述（定位/发展历程）、项目应用、社会价值 |
| 三、项目优势 | 产品服务、技术原理、创新点、技术可行性（论文专利列举） |
| 四、市场分析 | 行业分析、市场分析（数据须注明来源）、竞品分析 |
| 五、商业模式 | 盈利模式、运营模式、营销策略 |
| 六、团队介绍 | 团队组成、顾问指导 |
| 七、财务分析 | 财务规划、成本分析 |
| 八、融资需求 | 融资需求、股权架构、退出机制 |
| 九、风险控制 | 技术风险、市场风险、财务与融资风险 |
| 十、未来展望 | 短期规划（一年）、中长期规划（三年） |

常见限制：正文 12000 字以内；数据注明来源；支撑材料（论文/专利/合同）在申报系统上传。

## 三级标题体系

正式版采用清晰的三级标题，主次分明：

```
## 三、项目优势          （章：汉字数字）
### 2 技术原理          （二级：阿拉伯数字）
#### 2.2 信号提取       （三级：x.x）
```

重点章节（研究历程 / 产品 / 技术 / 市场 / 商业模式 / 财务）必须用三级标题展开，
不能只有一段文字带过。

## 重点章节展开要求

- **研究历程**：原理学习 → 原型开发 → 实验室实测 → 切中行业需求 → 工程化重构，
  每个阶段有实质内容（做了什么、验证了什么、为什么），配真实照片
- **产品**：每端（检测端 / 中控端 / 移动端）功能清单 + 界面截图对应，讲清部署形态
- **技术**：检测原理、信号提取各模块、统计检验各检测器、剂量估计、系统架构、
  数据流、两代演进，逐层展开，讲清原理与逻辑
- **逻辑衔接**：章节之间要有因果链
  （如：研究历程验证可行性 → 切中行业需求（多点、组网、留痕）→ 因此设计检测端+中控端分离）

## 常见比赛变体

### 计算机设计大赛（项目文档）

侧重：需求分析、系统架构、功能实现、技术难点、测试与部署。

### 互联网+ / 挑战杯（商业计划书）

侧重：市场分析、商业模式、财务预测、团队；按官方模板章节组织。

### 挑战杯·专项赛（如东北振兴产业升级专项赛）

- **评审五维度**：发展前景、市场价值、实践过程、创新意义、团队协作
- **专项主题落位**：围绕地区战略（如东北"五大安全"）映射项目价值
- **落地意愿**：有地区落地意愿 / 试点合作的项目有配套支持 → 单独写"落地规划"
- **脱敏**：提交材料须隐去学校名、学校标志、导师姓名
- **实践过程**：突出真实实验、调研、讨论照片（体现参与过程）

## 使用方式

- 阶段 1 先读官方模板与标准示例，输出 `01-赛事介绍.md` 与 `02-计划步骤.md`
- 块目录先给用户确认，确认后才执行
- **执行摘要最后写**：它由全部章节汇总而来，先写会造成返工；评委最先看，写完其他章节后集中打磨
