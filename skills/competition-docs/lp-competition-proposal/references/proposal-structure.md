# 计划书章节骨架

## 通用骨架（比赛项目文档）

| 章节 | 内容 | 主要来源 |
|------|------|----------|
| 执行摘要 | 项目一句话、痛点、方案、市场、模式、团队、融资 | 全部汇总（**最后写**） |
| 项目背景 | 国家战略、行业、技术背景 + 地区背景 | 调研 |
| 行业痛点与需求 | 现状、痛点（配数据）、需求趋势 | 调研 + 旧草稿 |
| 产品与技术 | 产品线、架构、算法、实现、实测验证 | 代码分析（可拆多块） |
| 创新点与差异化 | 技术亮点、竞品对比 | 代码 + 调研 |
| 市场分析 | 市场规模、目标用户、竞争格局 | 调研 |
| 商业模式 | 收入模式、定价、渠道、落地路径 | 调研 + 用户材料 |
| 实施计划 | 研发里程碑、时间线、团队分工 | 用户材料 |
| 财务与融资 | 财务预测、融资计划 | 用户材料 |
| 风险与对策 | 技术、市场、合规、运营风险 | 代码 + 调研 |
| 社会价值 | 社会 / 行业 / 用户价值 | 调研 |
| 附录 | 图表索引、参考文献、素材清单 | 汇总 |

## 常见比赛变体

### 计算机设计大赛（项目文档）

侧重：需求分析、系统架构、功能实现、技术难点、测试与部署。
图片必需：架构图、功能模块图、界面截图、数据库 ER 图、部署图。

### 互联网+ / 挑战杯（商业计划书）

侧重：市场分析、商业模式、财务预测、团队。
图片必需：Logo、产品界面、商业模式图；竞品对比用表格代替图片。

### 挑战杯·专项赛（如东北振兴产业升级专项赛）

在商业计划书基础上叠加专项要求：

- **评审五维度**：发展前景、市场价值、实践过程、创新意义、团队协作
- **专项主题落位**：围绕地区战略（如东北"五大安全"），把项目价值映射到专项主题
- **落地意愿**：有地区落地意愿 / 试点合作的项目有配套支持 → 单独写"落地路径"
- **脱敏**：提交材料须隐去学校名、学校标志、导师姓名 → 保留"暂不匿名 / 提交前处理"决策记录
- **实践过程**：突出真实实验、调研、讨论照片（体现参与过程）
- **材料清单**：简介（500 字）、商业计划书、PPT（≤20 页 PDF）、支撑材料、视频
- 先产出 `01-赛事介绍.md` 记录：组别、要求、时间线、评审维度、信息来源

## 重点章节拆分（按需）

通用骨架的"产品与技术"等核心章节可拆成多个块，逐块交付、逐块确认。
示例（两代产品双线详写）：

```
09-草稿-产品总览
10-草稿-老版本-技术方案
11-草稿-老版本-实测验证
12-草稿-新版本-系统架构
13-草稿-新版本-算法管线
14-草稿-新版本-中控端
15-草稿-两代演进
```

## 使用方式

- 用户提供的计划书要求（评分标准）优先于本骨架，按它调整章节
- 阶段 1 输出块目录（`02-计划步骤.md`）：章节表 + 每块内容来源 + 图片需求，等用户确认
- **执行摘要最后写**：它由全部章节汇总而来，先写会造成返工；评委最先看，写完其他章节后集中打磨
